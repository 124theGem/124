# Проверка MVP — 18 октября 2026, Europe/Astrakhan

## Установка и сборка

- Node.js **24.19.0**, npm **11.9.0**.
- `npm ci --no-audit --no-fund` выполнен по созданному lockfile; затем повторены сборка и тесты.
- `npm run build` — TypeScript и production-сборка проходят. Основной JS около **628 kB / 168 kB gzip**, CSS **15 kB / 4 kB gzip**. Vite предупреждает о чанке более 500 kB и аннотациях комментариев в Zod; ошибок сборки нет.
- `npm run dev` запускает приложение на 5174 и новый backend на 8003. Проверены HTML с заголовком Little Planets, модуль игрового запуска и настоящий ответ `/api/health`.
- Telegram SDK хранится локально с MIT-лицензией; SHA-256 записан в `public/vendor/README.md`. Внешние шрифты и игровые CDN не нужны.

## Автоматические тесты — 14/14

Десять проверок модели:

- Три стадии роста, 15-секундный цикл, однократный сбор урожая и возврат семян.
- Редкий 30-секундный рост после сериализации и закрытой вкладки.
- Отказ для занятых грядок и неподходящего биома.
- Проверка строительного пятна: дома, грядки, ресурсы, вода, площадка и границы.
- Отсутствие частичного списания при нехватке ресурсов.
- Восстановление источника через 20 секунд и защита от повторного сбора.
- Непроходимое основание истощённого источника: восстановившийся объект не запирает персонажа внутри.
- Путешествие через все три планеты с сохранением общего инвентаря, дома и посадки.
- Обязательный подход к кораблю, поиск пути вокруг грядок.
- Отклонение повреждённых сохранений.

Четыре серверные проверки:

- Правильная HMAC-подпись Telegram, включая дополнительное поле `signature`.
- Отказ при подмене, неверном токене, повторных полях, устаревшем и будущем `auth_date`.
- Настоящая SQLite на временном диске: повторное открытие базы, изоляция пользователей, конфликт ревизий.
- Fastify API: отсутствует вход по голому ID и dev-login; разрешены только подписанные действия. Проверены строительство, изменение инвентаря, HTTP 409, изоляция пользователей, неизвестные поля, занятое место и некорректный JSON.

## Браузерная игра

`npm run test:browser` проверяет настоящий Chromium/WebGL и реальные элементы интерфейса:

1. Запуск Листории, 3D-сцену, движение клавишей и ограничения количества draw calls.
2. Автоматический подход к грядке, выбор семени, три стадии роста по настоящему времени, сбор и семена.
3. 3D-предпросмотр домика, размещение и стоимость, открытие инвентаря.
4. Выбор настоящего ресурса кликом по проекции 3D-объекта, подход и добычу.
5. Посадку редкого растения, перелёты Листория → Мицелия → Пирос → Листория, общий инвентарь.
6. Сохранность растения и здания после возвращения и перезагрузки страницы.
7. Мобильный джойстик через настоящие touch events, портрет/альбом без горизонтального переполнения, браузерный fullscreen.

В тесте нет записи в игровой debug-интерфейс: диагностический объект даёт только снимок состояния и проекцию координат для кликов. Состояние меняется игровыми кнопками и движением. Обнаруженный при повторном прогоне короткий фиксированный sleep в проверке клавиатуры заменён ожиданием фактического движения: программный WebGL может пропускать такой короткий интервал ввода.

## Production и Telegram

`npm run test:production` запускает временный Fastify/SQLite и HTTP reverse proxy, снимающий префикс `/planets/`, как документированный `handle_path` Caddy.

- Production без Telegram показывает экран входа, локальный режим отключён.
- HTML, JavaScript, CSS, favicon, локальный SDK и API работают под префиксом.
- Настоящий Telegram bridge получает события эмулированного клиента Android 8.0; вызывает ready/expand/fullscreen и отключает вертикальные свайпы.
- Сумма safe areas 24 + 36 = **60 px** применяется к HUD.
- Подписанные искусственным тестовым токеном данные проходят настоящий серверный HMAC-путь. Домик строится через интерфейс, инвентарь в SQLite уменьшается, перезапуск клиента восстанавливает постройку.

Скриншоты находятся в игнорируемом `test-results/`: Листория, растущий сад, предпросмотр постройки, все три биома, мобильные ориентации и production Telegram.

## Границы проверки

Браузер — Chromium с программным SwiftShader в Linux. Его FPS не является измерением смартфона. Цели 30/60 FPS не подтверждены. Windows, настоящие Android/iOS WebView, публичный HTTPS, живой Telegram-бот и systemd на сервере владельца не запускались. Нативные события Telegram эмулировались, токен в тестах искусственный.

Теплица/склад пока декоративны; интерьеров, торговли, мультиплеера и продвинутой защиты от читов нет. У персонажа простые коллизии по сетке, боковые грани декоративны. Действующие Caddy/DNS/сервисы владельца эта работа не меняет.
