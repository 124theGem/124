# Проверка Colony 0.2 — 18 октября 2026

## Среда и сборка

Node.js 24.19.0, npm 11.9.0, системный Chromium `/usr/bin/chromium`.

- Повторно выполнено `npm ci --no-audit --no-fund` по lockfile.
- `npm run build` проверяет TypeScript и создаёт production frontend: JS около 666 kB / 180 kB gzip, CSS около 17 kB / 4.4 kB gzip. Сохраняются предупреждения Vite о размере чанка и комментариях Zod; ошибок сборки нет.
- `npm run dev`: проверены HTML, frontend entry point и `/api/health` на backend 8003. Для локальной игры Telegram-токен не требуется.
- Telegram SDK поставляется локально с лицензией; внешние игровые CDN и шрифты не нужны.

## Модель, сервер, сохранения — 26/26

`npm test`: 21 проверка модели и 5 серверных проверок.

Проверяются родная планета 38×38, ограничения зон строительства, площади зданий и коллизии, списание ресурсов, пакеты крафта и отсутствие повторной оплаты готового комплекта. Лаборатория открывает продвинутые рецепты. Модули требуют подходящий источник, копят ресурсы по серверному времени, ограничены буфером и получают дополнительную ёмкость от складов.

Проверены рост, сбор и семена, восстановление ресурсов, путь вокруг препятствий, четыре мира с общим инвентарём. В доме проверяются вход, сохранение комнаты, создание/размещение/возврат мебели, поворот, проход у двери, проходимый ковёр и выход на прежнюю наружную позицию. Метеорит даёт награду только после падения, вблизи и один раз; события воспроизводимы по времени сохранения.

Миграция версии 1 сохраняет инвентарь, посевы, истощённые источники и ревизию; переносит построенные игроком здания на Родную. Проверено, что результат записывается в настоящую SQLite и сохраняется после повторного открытия.

Проверены HMAC Telegram, текущий параметр signature, подмена данных, неверный секрет, просроченный/будущий вход, дубли параметров, изоляция пользователей, сохранение после открытия SQLite заново, конфликт ревизий, неправильные действия и отсутствие development-login в API.

## Production и обновление

`npm run test:production` завершён успешно после production-сборки. Изолированный backend и прокси проверяют маршрут `/planets/`, HTML/assets/SDK/API, запрет обычного браузерного входа, настоящую HMAC-подпись тестового initData, серверную SQLite, сохранение после перезагрузки и запросы fullscreen/безопасных областей через настоящий SDK с имитацией Telegram host.

`npm run package:server` формирует `releases/little-planets-colony-v2.tar.gz` и SHA-256. В пакете frontend, server/shared и lockfile, без `.env`, сохранений и node_modules.

`node tests/runtime.mjs` извлекает пакет во временную папку, реально выполняет `npm ci --omit=dev` и запускает его с одними production-зависимостями. Проверены HTML, health endpoint и запрет API без авторизации.

`npm run test:upgrade`: успешно пройдены три сценария — установка, отказ на повреждённом сохранении, возврат старого приложения и SQLite после провала проверки запуска. Используются настоящие временные каталоги, SQLite backup и HTTP; systemd, смена владельца и npm внутри этого теста заменены заглушками. Отдельный runtime-тест выше проверяет реальную установку npm.

## Практические ограничения

Реальный SSH-сервер пользователя не изменялся из этой среды. Обновление выполняется подготовленной командой на сервере. Старый формат базы несовместим со старым кодом после миграции: для ручного отката нужны обе резервные копии.

Настоящие Android/iOS WebView, физические телефоны, публичный HTTPS и реальный токен бота в облаке не использовались. Скорость кадров на смартфонах и нативный fullscreen конкретного Telegram-клиента требуют проверки устройством. Для входа через Telegram нужен серверный BOT_TOKEN и ранее настроенный HTTPS.
