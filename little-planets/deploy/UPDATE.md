# Обновление работающей Little Planets до Colony 0.2

Сценарий рассчитан на установленное приложение пользователя:

- `/opt/little-planets`, его закрытый `.env`;
- Node.js 24 в `/opt/little-planets-node`;
- сервис и отдельный пользователь `little-planets`;
- `HOST=127.0.0.1`, `PORT=8003`;
- `DATABASE_PATH=/var/lib/little-planets/planets.sqlite`.

Обновляющий файл проверяет эти условия перед изменениями. Caddy, DNS, бот и гонки обновления не требуют. URL Mini App остаётся `https://bot.razdorhouse.ru/planets/`.

Скачайте архив репозитория **конкретного опубликованного коммита**, распакуйте во временную папку и выполните от root:

```bash
/opt/little-planets-node/bin/node /ПУТЬ/К/РАСПАКОВАННОМУ/little-planets/deploy/upgrade.mjs /ПУТЬ/К/РАСПАКОВАННОМУ/little-planets
```

Используется готовый пакет `releases/little-planets-colony-v2.tar.gz`; пересобирать frontend на VPS не нужно. Проверяется его SHA-256, зависимости устанавливаются по lockfile в новую папку **до остановки игры**. Затем сценарий:

1. Останавливает только `little-planets`.
2. Делает согласованную SQLite-копию и проверяет миграцию всех сохранений, не меняя живую базу.
3. Сохраняет прежнюю папку приложения в `/opt/little-planets-backup-ДАТА/app`; `.env` копируется с правами 600.
4. Меняет папку приложения и запускает прежний systemd-сервис.
5. Проверяет локальный `/api/health`. При ошибке возвращает прежнее приложение и базу, затем запускает старый сервис.

Папка резервной копии выводится в терминал. Не удаляйте её до проверки игры через Telegram. Код архива, `.env` и база не попадают в общий системный конфиг. Токен сценарий не выводит. На момент переключения игра недоступна несколько секунд; зависимости скачиваются заранее. Установку зависимостей нельзя выполнить без доступа к npm registry.

После успешного обновления закройте Mini App полностью и откройте заново. Существующим игрокам нужно выбрать **Полёт → Родная**, поскольку миграция сохраняет текущую планету. Там доступны база и главный дом. Прогресс автоматически переводится в формат 2 при первом серверном чтении.

Для ручного возврата к старому коду после того, как игроки уже открывали новую игру, нужна и резервная копия **старой базы**: формат 2 старый код не понимает. Новые действия после резервной копии при таком возврате потеряются. Автоматический откат скрипта касается неудачного запуска непосредственно во время обновления.

## Проверка пакета при разработке

```bash
npm run package:server
npm run test:upgrade
```

Тест обновления исполняет сценарий в временных каталогах с настоящей SQLite и реальным HTTP health endpoint. Systemd, владельцы файлов и установка зависимостей заменены локальными заглушками. Проверяются успех, отказ до переключения на повреждённых сохранениях и восстановление старого приложения/базы после провала health check. Реальный systemd вашего VPS облачный тест не запускает.
