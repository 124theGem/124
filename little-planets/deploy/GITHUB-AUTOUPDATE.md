# Автообновление Little Planets через GitHub

VPS сам проверяет опубликованный канал релизов по HTTPS примерно раз в две минуты. Входящий SSH из среды Codex, GitHub Actions, токены GitHub и хранение root-пароля не требуются. Установка выполняется один раз через уже работающий SSH-вход пользователя.

## Что устанавливается

- `/opt/little-planets-updater/pull-release.mjs`: отдельный Node.js 24+ скрипт, сохраняющийся при замене приложения;
- `/var/lib/little-planets-updater/`: история релизов, блокировка и временные загрузки, доступ только root;
- два новых unit-файла: `little-planets-pull.service` и `little-planets-pull.timer`.

Существующий `little-planets.service`, `.env`, DNS, Caddy и street-racing установщик не меняет. Уже запущенная игра обновляется через проверенный `deploy/upgrade.mjs`: production-зависимости ставятся до остановки, приложение и SQLite копируются в `/opt/little-planets-backup-*`, сохранения проверяются, сервис запускается с прежним `.env`. При ошибке проверки/запуска upgrader восстанавливает прежнюю установку. Резервные копии автоматически не удаляются.

Текущий канал указывает на проверенный **Atlas 0.16**, коммит `7cccb796aeea62cd77e1def682acb98064d271e0`, SHA-256 `e8f6b818be04af6bb182c286b09e1c49a8afd5213b63bebdb55aacbc43b41f0a`.

Если все файлы установленной версии уже совпадают с проверенным архивом и health отвечает успешно, скрипт только запишет релиз в историю. Перезапуска и лишней резервной копии не будет. Перед применением дополнительно проверяется SQLite в режиме чтения: сохранения должны относиться к текущему поколению 3, а новый код сохранять этот маркер. При обнаружении старого поколения, которое сбросилось бы штатной миграцией, автообновление откажется до остановки игры и потребует отдельно подготовленную миграцию. Сброса прогресса нет.

## Однократное включение

Из SSH-сессии root запустите опубликованный установочный блок, закреплённый за точным коммитом репозитория. Он скачает только необходимые файлы установки и выполнит:

```bash
bash little-planets/deploy/install-pull-updater.sh
```

Установщик проверяет Node.js 24+, существующий `.env`, активный `little-planets` и доступность канала. Затем ставит собственные unit-файлы, включает таймер и сразу запускает первую проверку/обновление. Предыдущая история и локальная пауза при повторной установке сохраняются.

Для установки нужны `curl`, `tar`, `flock`, `install`, `systemctl`, Node.js в `/opt/little-planets-node/bin/node`. Ожидаемые параметры существующей игры: `127.0.0.1:8003`, база `/var/lib/little-planets/planets.sqlite`. Несовпадение останавливает установку до изменения unit-файлов.

## Как выпускается следующее обновление

Автообновление запускается только для явно опубликованного манифеста `deploy/channel.json`. Право публиковать этот файл в ветку `little-planets-mvp` управляет развёртыванием на подключённых серверах.

1. Завершить разработку и проверки, собрать серверный архив и SHA-256.
2. Зафиксировать и отправить коммит с готовым архивом в `little-planets-mvp`.
3. Подготовить манифест, указав **опубликованный коммит с архивом**:

```bash
cd little-planets
node deploy/promote-release.mjs FULL_COMMIT little-planets-NAME-v17.tar.gz 0.17.0
```

Команда проверяет синтаксис, локальный SHA, скачивает уже опубликованный коммит, сравнивает байты архива и версии source/package. Затем увеличивает числовой `release` и меняет только `deploy/channel.json`. С `--dry-run` проверяет всё без записи файла.

4. Проверить и опубликовать манифест отдельным коммитом:

```bash
git add deploy/channel.json
git commit -m 'release: promote verified Little Planets release'
git -c protocol.version=1 push origin HEAD:little-planets-mvp
```

Манифест ссылается на предыдущий коммит с протестированным пакетом. Это позволяет закрепить полный SHA без циклической ссылки коммита на самого себя. Ни одна обычная правка приложения сама по себе не меняет канал.

Публикация — отдельный явный шаг после успешных проверок; скрипт продвижения не запускает игровые тесты самостоятельно. `deploy/upgrade.mjs` в указанном коммите должен устанавливать именно указанный архив.

## Проверки и управление на VPS

```bash
systemctl list-timers little-planets-pull.timer
journalctl -u little-planets-pull.service -n 40 --no-pager
cat /var/lib/little-planets-updater/state.json
```

Проверка канала без установки:

```bash
/opt/little-planets-node/bin/node /opt/little-planets-updater/pull-release.mjs --check
```

При временной ошибке сети текущая игра продолжает работать; загрузка повторится на следующем запуске. Неудачная установка записывается в историю и блокируется от бесконечных повторных развёртываний того же релиза. После устранения причины повтор разрешается явно:

```bash
/opt/little-planets-node/bin/node /opt/little-planets-updater/pull-release.mjs --retry
```

Пауза дальнейших установок:

```bash
touch /var/lib/little-planets-updater/paused
```

Возобновление:

```bash
rm -f /var/lib/little-planets-updater/paused
systemctl start little-planets-pull.service
```

Отключение расписания:

```bash
systemctl disable --now little-planets-pull.timer
```

Отключение таймера не прерывает уже начавшееся обновление. Перед ручной заменой приложения отключите таймер и дождитесь завершения текущего `little-planets-pull.service`. Автоматические запуски и ручной запуск этого же скрипта защищены общей `flock`-блокировкой. Старые ручные команды `upgrade.mjs` напрямую её не используют.

В `channel.json` можно также опубликовать `"enabled": false` для общей паузы канала. Число `release` должно расти; изменить содержимое уже установленного номера или уменьшить номер нельзя. Для намеренного отката публикуется **новый номер** со ссылкой на прежний проверенный коммит/архив. Это не сбрасывает сохранения; совместимость старой версии с текущими данными необходимо проверить перед таким выпуском.

Сам обновляющий скрипт закреплён однократным установочным коммитом. Его изменение требует повторного запуска установщика; история установок сохраняется.

## Проверки реализации

- `node tests/pull-release.mjs`: 13 сценариев манифеста, проверки SHA, реальной распаковки, сохранения `.env`/прогресса, точного принятия установленной версии, ошибок сети, блокировки плохого релиза/повтора, паузы, истории и запрета ссылок.
- `node tests/pull-installer.mjs`: успешная установка и отказ при отсутствии сети, несовместимом `.env` и неактивной игре; все операции изолированы во временных каталогах со служебными заглушками.
- `npm run test:upgrade`: реальный механизм резервного копирования, проверка повреждённых сохранений и откат, изолированно с заглушкой systemd.

Реальный VPS автоматически этим тестом не изменяется. Первое подключение сервера к каналу подтверждается журналом после однократной установки пользователем.
